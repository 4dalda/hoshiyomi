# SHiKi 親近感LP レビュー用

## 開くページ
`assets/konkatsu-lp/friendly/index.html`

このZIPを展開して `assets/konkatsu-lp/friendly/index.html` を開けます。通常の静的HTTP配信にも対応します。既存の高級版 `assets/konkatsu-lp/index.html` は変更していません。

## 実装
- 指定コピーのファーストビュー、お悩み4カード、強み4項目。
- 元のWebP背景（118KB）と透過人物（184KB）を別レイヤーで使用。
- 180svhのヒーローとstickyシーン。背景、光、人物、文字の移動比率は0.09 / 0.19 / 0.43 / 0.63。
- スクロールイベントをrequestAnimationFrameに集約。逆スクロールで同じ位置に復元。
- スマホは155svh、移動量52%。prefers-reduced-motionではsticky延長と動きを無効化。
- 統一した線幅と色のオリジナルSVGアイコン、IntersectionObserverによる時間差表示。
- JS無効時も本文は表示。キーボードフォーカス、スキップリンク、ネイティブdialog対応。

## 実ブラウザ検証（2026-11-16 JST）

ローカルHTTP配信をChromium + Playwrightで描画。PC 1440×900、スマホ相当390×844。スマホ実機・タッチ慣性スクロール・Safariの検証ではない。

### 確認と修正
- 修正前の390pxで人物の髪がCTAに重なり、補足文にも重なっていた。スマホの人物サイズをシーンの59%から49%へ調整し、補足文の狭い幅制限を解除。修正後は重なり解消を静止画とスクロール録画で確認。
- スクロール途中に人物の下端が水平に現れた。人物レイヤーに下端のマスクを適用し、境界を柔らかくした。
- スマホのお悩み3番目の不自然な折り返しを調整。
- PC/スマホのヒーロー・お悩み・強み・スクロール途中を撮影。
- 実ホイールイベントで下方向、上方向、次セクションへの移動を録画（ブラウザページの画面録画。OS画面やカーソルの録画ではない）。
- スクロール進行0/25/50/75/100%で横はみ出しなし。逆スクロール後は文字レイヤーが初期transformに復元。
- PCの300pxスクロール時、背景Y=-33.75px、光=-71.25px、人物=-161.25px、文字=-236.25px。レイヤー位置の速度差を実DOM計測で確認。単なるopacityの変化ではない。
- 390pxでも速度差がある。PCより移動量を抑えているため、奥行き表現は控えめ。
- JavaScript実行エラーなし。CTAの案内ダイアログが開くことを確認。
- reduced-motionでは4レイヤーともcomputed transformがnoneになることをPC/スマホ幅で確認。
- WebM録画全フレームをffmpegでデコードし、抽出フレームを目視確認。MP4版はChromium内で再生時間の進行と末尾再生完了を確認。

### デザイン判断として残す点
- スマホの人物はCTAとの重なりを避けるため小さく配置。人物の存在感と余白のバランスはチャッピー・オーナーの判断対象。
- PCの人物はスクロール中に頭が先に画面外へ抜ける。速度差は成立しているが、この構図とマスクの柔らかさが意図に合うかレビュー対象。
- モック未提供のため、完成モックとの一致判定はできない。
- ヘッドレスChromiumの録画は実機の描画性能や操作感を保証しない。
